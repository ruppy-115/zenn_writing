# 「インデックスを貼る」とは？
まず「インデックスを貼る」とはどういうことなのか。
一言で表すとするのなら、「索引を作る」ということです。
辞書から一つの単語を見つけ出す時、1ページずつ捲って探していくのは大変なので、索引を見て目的のページを開くと思います。
それと同じことをDBでもやってあげようということなのです。

# なぜ速くなる？「B-Tree構造」の仕組み
ではなぜ索引を作ると速くなるのでしょうか。
その秘密は、「目的のデータにたどり着くための方法」にあります。

インデックスを貼らなかった場合、一つのデータを探すにはDBの中にあるデータを一件ずつ見ていきます。
この探し方を「線形探索(せんけいたんさく)」と言います。
10件のデータがあり、目的のデータが一番最後にある場合、10件のデータを見ていくということです。
（よくO(n)と表されていますね。nにはデータの個数が入ります。）

インデックスを貼った場合、多くのデータベースでは、「B-Tree構造」が作られます。
これは、ルートノード、ノード、リーフノードからなるものです。
ルートノードより大きいものは右、小さいものは左と分岐していくことで探索の回数を大幅に減らすことができます。

# 【要注意】インデックスを貼りすぎるとダメな理由
では、インデックスを貼りすぎるとダメなのは、なぜでしょうか。
B-Tree構造では、データの追加や削除が行われた際、ノードを再構成します。
そのため、インデックスを貼りすぎると、そういった操作が重たくなってしまうのです。

# どんな時にインデックスを貼るべきか
インデックスは、カーディナリティが高いカラムに貼ると効果が大きく出ます。
条件として指定した場合に、絞り込める数が多くなるためです。
性別カラムよりもメールアドレスに貼る方が、インデックスの効果を十分に発揮することができるのです。
